# Bufr 3.0 — скроллинг-захват

## Контекст

Скроллинг-захват делает один длинный скриншот прокручиваемой области: страницы, чата, документа, списка. В основной спецификации 3.0 он был «вне рамок v1». Теперь его добавляем в тот же выпуск **3.0.0**, пока тот не опубликован. Всё, что уже есть, переиспользуется:

- выделение области;
- путь «снимок → PNG → история → папка → буфер → Quick Access»;
- разрешения;
- хоткеи.

Основная спецификация: `2026-09-23-screenshots-design.md`.

### Решения пользователя
| Вопрос | Решение |
|---|---|
| Прокрутка | **Оба режима**: вручную (колесо или трекпад) и «Авто» (Bufr прокручивает сам). Переключаться можно во время захвата |
| Выпуск | В составе 3.0.0, версия не меняется |
| Источник кадров | **Видеопоток ScreenCaptureKit** (`SCStream`) по выделенной области, около 12 кадров/с |

## Ключевые технические решения

| # | Решение | Почему |
|---|---|---|
| S1 | Сначала обычное выделение области (тот же оверлей с лупой, режим «область»). После отпускания мыши затемнение исчезает и начинается **живой** захват | Выделение пользователь уже знает. Во время прокрутки кадр не должен быть заморожен |
| S2 | Кадры — `SCStream` с фильтром дисплея **без окон Bufr** (`excludingApplications: [Bufr]`, как в D4/D5). В `SCStreamConfiguration.sourceRect` — выделенная область, `minimumFrameInterval` 1/12 с, BGRA, без курсора | Рамка и панель управления Bufr лежат поверх области, но в кадры не попадают. Больше кадров — надёжнее склейка при быстрой ручной прокрутке |
| S3 | Склейка — отдельный чистый модуль `ScrollStitcher` без UI и без ScreenCaptureKit, на вход только `CGImage`. Кадры обрабатываются вне главного потока, по одному: пока идёт обработка, новые кадры отбрасываются (берётся самый свежий) | Модуль тестируется на синтетических «страницах». Интерфейс не тормозит |
| S4 | Растёт только **вниз**. Прокрутка вверх (содержимое уже снято) игнорируется | Так устроены длинные снимки в CleanShot и ему подобных. Нет неоднозначности, куда клеить |
| S5 | Прилипающие шапки и подвалы находятся автоматически. Это строки сверху и снизу, одинаковые в соседних кадрах, при том что середина сдвинулась. В результате шапка стоит один раз сверху, подвал один раз снизу | Почти у каждого сайта и мессенджера есть закреплённая шапка. Без этого она повторялась бы через каждый экран |
| S6 | Предел — 30 000 px высоты или 60 Мп (что наступит раньше): захват останавливается с уведомлением | Память: 60 Мп × 4 байта = 240 МБ на холст |
| S7 | «Авто»: `CGEvent` прокрутки (в пикселях) в центр области, шаг — половина высоты области. Следующий шаг — после обработки кадра. Конец страницы — 3 шага подряд без сдвига: авто останавливается, «Готово» остаётся за пользователем | Нужен «Универсальный доступ» (он уже нужен для вставки). Половина высоты оставляет надёжное перекрытие |
| S8 | Return и Esc во время захвата — временные глобальные хоткеи (как остальные, через HotKey). Повторное нажатие сочетания скроллинг-захвата = «Готово» | Панель неактивирующая: клавиатура остаётся у прокручиваемого приложения. В отличие от других режимов, здесь уже накоплена работа, и повторное нажатие её не выбрасывает |
| S9 | Распознавание текста длинных картинок идёт **по частям**. Если высота больше 6144 px и в 2 раза больше ширины, картинка режется на полосы до 4096 px с перекрытием 200 px. Строки на стыке не дублируются | Сейчас картинка уменьшается до 6144 px по длинной стороне, и в длинных снимках весь текст пропадает (отложенная мелочь M3 #8). Поиск по скроллинг-снимкам без этого бесполезен |

## Модули (N — новый, M — изменённый)

```
Sources/
  Capture/
    Scrolling/  ScrollStitcher N        чистая склейка: append(frame) → результат, compose() → CGImage
                ScrollFrameSource N     SCStream по области → последний кадр CGImage (протокол + реализация)
                AutoScroller N          CGEvent прокрутки + политика «конец страницы»
                ScrollingCaptureSession N  состояние сеанса, связывает источник, склейку, авто, панели
                ScrollingCapturePanels N   рамка (пропускает клики) + панель управления (SwiftUI)
    CaptureMode M       + .scrolling
    CaptureSessionController M  выделение для .scrolling отдаёт область, не снимок
    Overlay/AllInOneToolbar M   + кнопка «Прокрутка»
  Models/HotKeyAction M          + captureScrolling (⌥⇧⌘4 по умолчанию)
  Screenshots/ScreenshotCoordinator M  запуск сеанса, результат → process(CaptureOutcome)
  OCR/OCRIndexer M               распознавание длинных картинок по частям
  Views/MenuBar/MenuBarView M    пункт «Скроллинг-захват»
```

## Склейка (`ScrollStitcher`)

**Интерфейс:**
- `init(firstFrame: CGImage, maxHeight: Int, maxPixels: Int)`
- `append(_ frame: CGImage) -> Step`, где `Step`:
  - `.added(rows)`;
  - `.noMovement`;
  - `.movedUp` — игнорируется;
  - `.lostTrack` — рывок больше, чем позволяет перекрытие;
  - `.limitReached`.
- `height`, `preview(maxSize:)`, `compose() -> CGImage?`

**Алгоритм:**
1. **Подпись строки.** Кадр переводится в оттенки серого шириной 64 колонки, строка = вектор из 64 байт. Сравнение — средняя абсолютная разность (SAD).
2. **Прилипающие полосы.** Сверху и снизу считаются подряд идущие строки, совпадающие с прошлым кадром на той же высоте. Это шапка H и подвал F, если середина сдвинулась. Шапка берётся из первого кадра, подвал — из последнего.
3. **Сдвиг.** В подвижной полосе `[H, h−F)` ищется `d ≥ 1` такой, что строки нового кадра `[H, h−F−d)` совпадают со строками прошлого `[H+d, h−F)`:
   - минимальное перекрытие — 25% полосы;
   - лучший `d` принимается, если SAD ниже порога и заметно лучше соседних;
   - `d = 0` → `.noMovement`;
   - совпадение при сдвиге вверх → `.movedUp`;
   - ничего не подошло → `.lostTrack`, кадр пропускается, подсказка «Прокручивайте медленнее».
4. **Добавление.** Нижние `d` строк подвижной полосы нового кадра дописываются в холст.
5. **Сборка.** Шапка + холст + подвал (из последнего кадра) → один `CGImage` в цветовом пространстве кадров.

## Сеанс и интерфейс

**Состояния:** `selecting → capturing(manual | auto) → finishing | cancelled`.

1. **Запуск:**
   - режим «Прокрутка» на панели ⇧⌘5 (берётся текущее выделение);
   - пункт меню «Скроллинг-захват»;
   - хоткей `captureScrolling` (⌥⇧⌘4, переназначаемый, с проверкой конфликтов, как остальные);
   - без «Записи экрана» — тот же помощник по разрешению.
2. **Выделение** — оверлей в режиме «область». Space (окно) и Return (прошлая область) здесь тоже работают: результатом всегда будет область. Отпускание мыши заканчивает выделение, оверлей закрывается.
3. **Захват:**
   - **Рамка** — borderless-панель по контуру области со штриховой линией снаружи. `ignoresMouseEvents`, не мешает прокрутке.
   - **Панель управления** — неактивирующая панель под областью; если снизу нет места, то над ней, а если и там нет — в углу экрана. На ней:
     - «Авто» (вкл./выкл.);
     - «Готово»;
     - «✕»;
     - размер «1280 × 6400 px»;
     - превью склейки до 4 обновлений в секунду;
     - подсказка: «Прокрутите область вниз» / «Прокручивайте медленнее» / «Конец страницы» / «Достигнут предел».
   - **«Авто» без «Универсального доступа»** — подсказка с кнопкой «Открыть настройки», ручной режим продолжается.
4. **«Готово» / Return / повторный хоткей:**
   - поток останавливается, `compose()`;
   - `CaptureOutcome` (pointScale дисплея, источник — приложение под областью, `screenRect` = область) → `ScreenshotCoordinator.process`;
   - дальше как у любого скриншота: звук, история, папка, буфер, «после снимка» (Quick Access / редактор / закрепить).
5. **Отмена** — Esc, «✕», смена конфигурации экранов или ошибка потока (с уведомлением): ничего не сохраняется.
6. **Во время сеанса:** хоткеи других режимов игнорируются, распознавание в фоне на паузе не ставится (Vision и так идёт по очереди).

## Распознавание длинных картинок (S9)

- `OCRIndexer` решает, резать ли картинку, по её размеру из метаданных — без полной загрузки.
- **Полосы** по 4096 px с перекрытием 200 px. Ширина больше 6144 px уменьшается пропорционально.
- Текст полос склеивается. Строки из первых 200 px полосы, совпадающие с последними строками предыдущей, отбрасываются.
- Тот же путь используют «Скопировать текст» и индексация.

## Проверка

**Юнит-тесты:**
- `ScrollStitcherTests` на синтетических страницах (строки с уникальным рисунком):
  - равномерная прокрутка восстанавливает страницу пиксель в пиксель;
  - разный шаг прокрутки;
  - шапка есть в каждом кадре → в результате один раз;
  - подвал;
  - прокрутка вверх игнорируется;
  - рывок больше кадра → `.lostTrack`, следующий нормальный кадр продолжает склейку;
  - без движения → `.noMovement`;
  - предел высоты → `.limitReached`.
- `AutoScrollPolicyTests`: шаг = половина высоты; конец страницы после 3 шагов без сдвига; ручной сдвиг сбрасывает счётчик.
- `OCRTilingTests`:
  - нарезка полос (границы, перекрытие, широкая картинка);
  - длинная картинка с текстом наверху и внизу → оба найдены;
  - строка на стыке полос не дублируется.
- Хоткей: у `captureScrolling` значение по умолчанию ⌥⇧⌘4, конфликтов с другими действиями нет.

**Ручная проверка** (в чек-лист 3.0):
- Safari и Chrome: длинная статья с прилипающей шапкой;
- чат (Telegram или Slack), Finder-список, PDF в Просмотре;
- быстрая ручная прокрутка трекпадом → подсказка «медленнее» и продолжение;
- «Авто» до конца страницы;
- без «Универсального доступа»;
- Retina и внешний дисплей;
- поиск находит слово из нижней части длинного снимка.

## Риски
- **Анимированная прокрутка и параллакс** (сайты с плавным скроллом, фоны, видео) дают ложные совпадения или потерю сдвига. Смягчение:
  - порог SAD и требование «заметно лучше соседних»;
  - `.lostTrack` не портит холст;
  - в заметках к выпуску честно сказано, где склейка может ошибаться.
- **Живые элементы** внутри области (мигающий курсор, счётчики) слегка отличаются между кадрами — сравнение по SAD с порогом, а не на точное равенство.
- **Значок записи экрана** в строке меню горит во время захвата — это нормально, в заметках к выпуску упомянуть.

## Вне рамок
Горизонтальная прокрутка, захват видео, автоматический выбор прокручиваемого элемента без выделения.
